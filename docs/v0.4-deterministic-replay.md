# CSD Foundry v0.4 Deterministic Replay

## Scope

Replay policy version 1 establishes one bounded, single-producer choice session per attempt,
an immutable operation-specific choice ledger, exact independent replay, strict sequential
lowest-valid-attempt resolution, and structured search-exhaustion evidence. It does not
establish planner completeness, state or event construction, oracle-valid trajectories,
worker scheduling, shard merging, infeasibility, or release-scale output.

## Replay policy compatibility

The generation namespace already commits to this exact policy document:

```json
{
  "policy_id": "csd-replay-contract",
  "policy_version": 1,
  "semantic_execution_mode": "lowest-valid-attempt"
}
```

Packaging the document does not change its canonical digest. A semantic behavior change
requires replay policy version 2 and separate immutable evidence.

## Attempt inputs and explored branches

`AttemptInputCommitment` binds an attempt to a producer contract and canonical payload
without assuming planner or constructor semantics. `SearchBranchCommitment` binds that
input commitment, the choice-ledger commitment, and normalized branch facts. The rejection
diagnosis is excluded from the branch commitment so independent verifiers can refer to the
same explored branch while reporting different findings.

## Choice session

A `ChoiceSession` owns one attempt, one producer contract, and one declared choice-path
namespace prefix. It enforces exact positive limits on choice count and canonical ledger
bytes. A path is reserved before primitive execution. Any exception after reservation
poisons the session permanently: the path is not released, no further choice may execute,
and the session cannot freeze a semantic ledger.

Ledger-facing weighted values use the immutable canonical-value algebra. Integer `1`,
string `"1"`, and Boolean `true` remain distinct. Floats, mutable containers, arbitrary
objects, subclasses, duplicate paths, cross-attempt paths, and undeclared namespace
prefixes fail closed.

## Ledger and replay

One attempt produces one `ChoiceLedger`; partial-ledger merging is outside this policy
version. Runtime call order is not semantic. Records are sorted by canonical choice-path
bytes, so equal record sets yield equal ledger bytes and digests regardless of call order.
Independent replay recomputes every primitive choice, draw sequence, domain commitment,
material commitment, selected result, identity record, and ledger digest.

## Attempt completion

Semantic attempts are exact `AttemptAccepted` or `AttemptRejected` values. Operational
timeout, cancellation, process termination, or infrastructure failure is represented by
`OperationalAttemptBlock` and cannot enter semantic completion or exhaustion evidence.

Acceptance at index `n` requires exact rejected coverage of indices `0..n-1`, acceptance at
`n`, and no semantic completion after `n`. Duplicate indices, gaps, out-of-range indices,
multiple acceptances, and post-acceptance completions fail closed. Missing lower attempts
produce an explicit incomplete-prefix result rather than acceptance or rejection.

## Exhaustion

`ExhaustionEvidence` requires exact rejection coverage of the full declared `AttemptRange`.
It retains compact completion commitments, cause/owner/detail histograms, normalized facts,
and candidate constraint identifiers. Full replay bundles are independent diagnostic
evidence and need not remain live in memory after validation.

Exhaustion is bounded search evidence only. There is no conversion method from exhaustion
to `InfeasibilityWitness`; a later independent bounded checker must verify any contradiction
or unsatisfiable core.

## Frozen evidence

Replay canary version 1 contains seven vectors: acceptance at attempt zero, a rejected
prefix followed by acceptance, complete exhaustion, call-order independence, typed weighted
domains, forced redraw preservation, and identity-ledger commitment. The vector catalog and
all expected digests are independently pinned. In-place mutation fails validation; behavior
changes require a new replay evidence version.
